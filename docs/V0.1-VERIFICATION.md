# V0.1 verification report

Verified locally on 19 November 2026 (Europe/Amsterdam).

## Outcome

V0.1 passes its local foundation build, application, security-pipeline and
Chromium smoke checks. It is not approved for public production use or real
customer data. V0.2 has not been started.

## Implemented changes

- Created Git at the workspace root; original source checkpoint is 9637633.
- Added HappyAlmere.slnx containing four existing layers and foundation tests.
- Pinned installed .NET SDK 10.0.403; verified ASP.NET runtime 10.0.14.
- Centralized build settings, nullable checking, warnings-as-errors and NuGet audit.
- Added VS Code build/test/run tasks, HTTPS debug launch and extension recommendations.
- Moved CI to the actual Git root and added restore, Release build and tests.
- Split application contracts/service into individual files; added centralized
  bounded search validation and an async, cancellation-aware repository contract.
- Added a typed view model; search retains its category and shows its selected
  category. Added an explicit Dutch warning against personal information input.
- Preserved the four-layer architecture, demo data and framework DI.
- Strengthened security-header handling for exceptions; added secure antiforgery
  cookie settings, no-referrer policy and response-level noindex; disabled Kestrel
  identification headers. Existing HTTPS, HSTS, CSP and rate limits remain.
- Converted responsive overrides to mobile-first CSS without adding frontend libraries.
- Added 31 automated .NET tests and a reusable optional Chromium smoke script.
- Added architecture, security, run instructions and this report.

## Environment issues resolved

The .NET template cache required approved access outside the workspace sandbox.
An initial parallel solution build failed without compiler diagnostics; serial
MSBuild with disabled build servers succeeded. A build attempted while the app
was running encountered Windows DLL locks; stopping that owned app resolved them.
Final results above are from successful builds after resolving those conditions.

The sandboxed server could bind HTTPS but TLS handshakes failed. Running Kestrel
outside the sandbox with access to the trusted development certificate resolved
the problem. Chromium also required approved process-launch access. Neither TLS
validation nor application security controls were relaxed. No certificates were
exported into source control. Owned local server processes were stopped after QA.

## Remaining limits and release gate

- No PostgreSQL/EF Core implementation, migrations or database security tests.
  These are explicitly future storage, not claimed as implemented.
- No authentication, authorization, administrator workflow or real customer capture.
- HappyUtrecht support is a documented design path; city isolation is not implemented.
- No mobile API exists; the service boundary can support future versioned DTOs.
- Shared per-process limiting needs production redesign and load testing.
- GET search terms can enter browser history and logs.
- No comprehensive WCAG/contrast/screen-reader audit, cross-browser/device matrix,
  performance benchmark or penetration test has been completed.
- VS Code configuration and its Debug build were verified; an interactive F5
  breakpoint session was not exercised. Remote GitHub Actions has not run.
- Dependency auditing reflects the available advisory data, not a security guarantee.
- Production deployment requires the controls and reviews in SECURITY.md.

Two owner business-plan files (Markdown/PDF) appeared in the workspace during the
work and were left untouched and untracked. The Markdown's proposed Nuxt/API stack
differs from this assignment's mandatory MVC/Razor architecture. This assignment
takes precedence; no Nuxt migration or business-plan revision was performed.
The business plan's research and PDF content were not independently validated.

V0.1 is verified for local prototype use. Future development requires a separate
scope; this work does not authorize public deployment or collecting customer data.
